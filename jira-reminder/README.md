# Jira 工作提醒

Windows 本机应用：独立窗口、快捷方式、系统托盘、企业微信、Jira 临期检查和 Codex 对话。

## 安装

从 [GitHub Releases](https://github.com/JackDows/jira-reminder/releases) 下载 `JiraWorkReminder-版本-Setup-x64.exe`，双击安装。支持 **Windows 10 2004（19041）及以上、Windows 11，x64**。携带 Node.js 24.15.0、Codex CLI 0.154.0；缺少 WebView2 时需要联网，由安装器补装。

完成后双击 **Jira 工作提醒**。个人数据在 `%LOCALAPPDATA%\JiraWorkReminder`，程序默认安装到 `%LOCALAPPDATA%\Programs\JiraWorkReminder`，升级和卸载保留个人数据。当前安装包未做发布者代码签名，Windows 可能提示未知发布者；发布页提供 SHA-256 文件供核验。

## 首次使用：两种入口任选

### 没有备份：直接新建配置

1. 设置 → **登录 Codex**，在自动打开的官方网页登录；本机已有登录可直接使用。
2. 填写 Jira 用户名、密码，点击 **验证并保存**。
3. 创建或使用企业微信智能机器人，选择 API 模式长连接，填写 Bot ID、Secret。
4. 按页面提示在机器人单聊发送绑定码，确认消息收发和本机通知。
5. 点击 **恢复提醒**。

不需要备份。以后也能独立更换账号和机器人，更换 Bot ID 时重新绑定本人。

### 有备份：恢复旧电脑配置

1. 旧电脑设置 → **备份与迁移 → 导出加密备份**，设置至少 12 个字符的密码。
2. 保存 `.jwrbackup` 文件和密码；包含机器人、绑定人、Jira 凭据、工作记录、对话、完成标记和发送记录，不含 Codex 登录令牌。
3. 旧电脑托盘 → **退出并暂停提醒**，并移除旧机自启动，避免两台电脑争用同一机器人。
4. 新电脑选择 **从备份恢复**，输入密码并确认替换。
5. 导入后自动重启后台，提醒先暂停；重新登录 Codex，检查连接后恢复提醒。

忘记备份密码无法解密该文件，但仍能重新配置账号继续使用。工作历史只能通过可用备份找回。迁移后以**新电脑**的开机、休眠和联网情况决定是否提醒。

备份使用 scrypt 派生密钥和 AES-256-GCM 加密及完整性校验。导入后用新 Windows 用户的 DPAPI 保护凭据；先完整写入新目录，重启时原子切换，旧目录保留。错误密码和损坏文件不修改现有数据，也不会重发旧的待发送消息。备份和个人数据单独保存，不提交 GitHub。

## 日常使用与对话

### 工作历史

连接 Jira 后自动载入过去两个日历月的本人标准工时记录（以北京时间为准）。包括已完成和已改派任务；按照记录作者筛选。工作历史页可按日期、任务编号和正文搜索，并手动重新同步。后续每天 15:00 起刷新最近两个月，保留已载入的更早历史。查询受当前账号的 Jira 可见权限限制。

历史记录保留日期、描述、任务链接、工时、来源和原始编号，可作为日报／本周周报素材；不会自动修改今日完成标记。完整查询成功才替换对应区间，重复同步不会追加重复项。历史也包含在加密备份内。

来源记录放在 `state.activities`，同步状态放在 `state.sources`，与手工对话和提醒状态分开。当前只实现 Jira；后续加入 Confluence、Bitbucket 可沿用来源标识、原始编号、时间、正文与链接，没有预建插件框架或空接口。

- **今日工作**：实际运行状态、完成标记、临期任务和下一次提醒。
- **记录与整理**：日报、周计划、聊天分别保存对话；可连续说“删掉这一项”“补充现场联调”。
- 企业微信发送 **日报**、**周报**（或 **周计划**）、**聊天** 切换模式，随后直接回复，不用重复前缀。每天默认回到日报。
- **已填报** 记录今日完成；**撤销完成** 取消误操作；**状态** 查看完成状态；**测试** 检查收发；**重试** 重新整理失败的内容。
- **今天晚上六点再提醒我**、**18:30再提醒我**、**半小时后提醒我**：调整今天的填报提醒，到点自动执行。再次指定时间会替换前一次；**取消稍后提醒** 恢复当天默认安排。时间不明确时会请你补充，不会交给模型猜测执行。工作台也可选择时间。
- 日报描述最多 50 字，仍需自行填报。生成草稿不等于已填报。
- 没有固定对话轮数上限，单条最多 4000 字。全部记录与对话保存在本机；每次回答带当前草稿、近期工作资料及最近最多 40 条／24000 字对话，更早的细节可能需要再次补充。
- Codex 只接收工作内容，不接收 Jira 和机器人密码。调用使用当前账号额度；不继承其他 Codex 任务的历史，不代替你执行外部操作。

关闭窗口收至托盘，后台继续。**退出并暂停提醒** 会暂停、断开机器人并停止后台；重新打开后可恢复提醒。下次登录 Windows 会再次启动应用。迁移旧机应移除自启动，避免旧机重新连接机器人。

## 提醒规则（北京时间）

- 电脑运行视为工作，周末和调休开机也提醒。
- **15:00**：询问日报填报；检查所有分配给本人的未完成任务，提醒今天、明天、后天到期的项目及链接。日报、临期列表和周计划分别发消息。
- **周六 15:00**：核对本周工作和下周计划，不直接定稿。
- **22:00**：当天未确认填报时，企业微信与本机再提醒；已完成则安静。
- 当天改期保存在本机，重启后仍有效；已填报会取消待提醒。改期不影响临期和周计划检查。约定在22点之后时，夜间复查一起推迟到约定时间；第二天恢复默认安排。相对时间向上取整到分钟。
- 晚开机或恢复联网后约 15 秒内补执行当天未完成检查。22 点后首次启动合并两轮。
- 离线本机提示联网；关机、休眠不运行、不唤醒电脑、不补发昨日提醒。
- 本地保存发送记录，通常重启不重复；平台已收消息但确认丢失时，重试仍可能重复一条。

使用 Jira 标准 `duedate` 字段，查询失败不当作零任务，五分钟后重试。本版本连接 `https://jira.aonorx.com` 的 Jira Server REST API v2。通知显示受 Windows 通知设置影响，工作台保留检查状态。

## 源码与构建

仓库根目录 `.github/workflows/release.yml` 是发布入口，应用源码在 `jira-reminder/`。

```powershell
cd jira-reminder
npm.cmd ci
npm.cmd test
.\packaging\Build-Release.ps1
```

构建依赖 Windows .NET Framework 4.8 编译器、WebView2 SDK 1.0.4191.47、Node.js 24.15.0、Codex CLI 0.154.0、Inno Setup 6.7.3。固定下载校验 SHA-256，WebView2 引导安装器验证微软签名。第三方许可随包携带。

开发版使用 `Start.ps1` 启动，数据在 `.local`；同一 Windows 用户首次安装时尝试迁移开发版数据，旧文件保留。`Install-Autostart.ps1` 注册当前用户任务 `Aonor-Jira-Reminder`；`Remove-Autostart.ps1` 移除自启动。PowerShell 脚本采用带 BOM 的 UTF-8。

推送提交后 Actions 可手动构建；推送与 `package.json` 一致的 `v0.3.1` Tag 自动构建并发布 Release。产物在 `dist/`，明确列出文件打包，不包含个人数据、登录令牌、日志和备份。

机器人与桌面共用 `WorkService.setReminder(time)`：本机 `POST /api/work/reminder` 接受 `{"time":"18:00"}`，取消使用 `{"time":null}`，沿用页面会话令牌校验。只允许当天未来时间，不直接修改每日默认规则；备份导入会清除旧的待改期提醒。

## 验证

自动测试使用虚构数据，覆盖提醒边界、离线补执行、重复消息、Jira 分页、DPAPI、备份篡改、导入切换、无备份初始化、多轮上下文及本机接口控制。真实企业微信、Windows 通知和新机器网页登录需在实际设备确认。
