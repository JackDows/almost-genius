# Almost Genius · v0.4.2 预览版

本机运行的个人 AI 助手，支持独立窗口、系统托盘和企业微信。
本版供验收与试用，v1.0.0 等用户验收、实际使用稳定后再发布。

## 安装

从 [GitHub Releases](https://github.com/JackDows/almost-genius/releases) 下载 AlmostGenius-0.4.2-Setup-x64.exe。
要求 Windows 10 2004 或更新版本、Windows 11，x64。安装器内含 Node 24.15.0、Codex CLI 0.154.0；缺少 WebView2 时会联网安装。

安装后点击桌面的 **Almost Genius**。关闭窗口会收到托盘；右键可打开、确认填报、暂停提醒或退出。
“登录后自动运行”指登录 Windows，不是登录 Jira。机器关机、休眠时不运行也不唤醒。

已有 Jira 工作提醒可直接覆盖升级。安装身份、数据目录与加密方式保留兼容，桌面入口改为新名称。
新安装默认在 %LOCALAPPDATA%/Programs/AlmostGenius，旧安装沿用原位置；个人数据仍在 %LOCALAPPDATA%/JiraWorkReminder。

## 首次配置和迁移

在设置中连接企业微信机器人（API 模式长连接）、填写 Jira 用户名密码、登录 Codex。
机器人绑定到你的单聊账号，只响应和推送给该账号。密钥用当前 Windows 用户的 DPAPI 加密保存。
Codex 通过官方网页登录，使用账号额度；不需要另外填模型 API Key。

备份是可选的：可以从零配置，也可以导入旧电脑的 .jwrbackup。
加密备份包含机器人/Jira 配置、工作历史、任务、对话和成长档案；Codex 登录在新电脑重新完成。
迁移前停用旧电脑后台，导入后检查连接再恢复提醒。忘记备份密码无法解密，但仍能重新配置使用。

## 日常使用

**聊一聊** 和企业微信共用个人对话。没有固定轮次上限；上下文只发送最近对话，长期资料按需检索，仍受 Codex 额度和网络影响。

可直接说：

- “每周五18点提醒我记录本周学习收获。”
- “把学习提醒改到周日20点。”
- “暂停这个任务”“恢复运行”“删除它”“撤销刚才的修改”。
- “今天晚上六点再提醒我填日报。”
- “今天处理了通讯超时和设备联调，帮我整理填报内容。”
- “把这个项目经历保存为待核对记录。”

创建任务是组合已经接入的能力，不包含自动安装插件、编写脚本或接入全新的公司系统。
常规任务支持单次、每天、每周和至少5分钟的间隔执行。任务可以直接发提醒，或由 AI 使用指定资料执行。
Jira、日报、周核对类型沿用内置处理逻辑；需要自定义处理步骤时选择“AI 根据说明执行”。

**我的任务** 显示计划、启停状态、最近执行结果，可创建和编辑；删除可恢复，修改有版本冲突检查。
“跳过错过的时间”只在到期后一分钟内执行；“当天补执行”在当天启动／联网后补最近一次，旧日不补。
全局提醒暂停时，新增任务也不会自动运行。

默认任务（北京时间）：

|任务|时间|行为|
|---|---|---|
|日报填报|每天15:00、22:00|已填报则当天停止；草稿不等于完成|
|Jira 临期|每天15:00|本人所有未完成任务，今天至后天到期，带日期与链接|
|周计划核对|周六15:00|用本周工作记录询问补充和下周计划|

没有工作日过滤，周末开机也按任务提醒。未联网时本机提示联网，联网后补查；晚于22点首次启动合并当天催报。
回复“已填报”或点击今日完成，标记保存在本地。日报不超过50字，周报先核对草稿。

## 个人成长档案

记录类型包括经验、技能、项目、偏好和链接收藏。个人背景采用 TELOS 的目标/挑战/项目/偏好结构。
“从工作历史提炼候选”会读取已加载的历史、查重并先生成最多10条候选供核对，可继续要求处理下一批。
候选不代表已掌握；用户确认后才进入已确认状态，修改内容后会重新待核对。
证据保存来源编号和当时的原文，即使以后同步范围缩小或公司账号失效，已归档经历仍保留。

“导出个人档案”得到 Markdown 和 JSON，不包含账号密钥；加密备份用于完整恢复。
原始工时、精简日报、AI 对话、个人档案分别保存。Confluence、Bitbucket 等以后可以增加数据来源，无需改变任务和档案的存储方式。

## 开发

安装 Node 24 后，在本目录运行：

```powershell
npm ci
npm test
npm start
```

本机网页默认 http://127.0.0.1:60500/。开发数据在 .local；测试可设置 JIRA_REMINDER_DATA 和 JIRA_REMINDER_PORT 使用独立目录与端口。

主要模块：

- tasks.mjs / task-scheduler.mjs：任务定义、修订、当天调度、渠道送达记录。
- assistant.mjs / codex.mjs：持久化对话队列、Codex 运行与失败重试。
- agent-tools.mjs / mcp.mjs：每轮授权的本机工具；UI 与 AI 复用同一业务服务。
- archive.mjs：候选、确认、证据快照、中文检索与个人导出。
- history.mjs / jira.mjs：原始 Jira 工时和临期查询。
- backup.mjs：兼容旧备份、导入校验、加密和原子切换。

定时 AI 任务不能管理其它任务或确认档案；只拿到勾选的资料能力。工具令牌每次运行结束失效，Jira/企业微信密钥不会给模型。
Codex 运行使用临时参数，不更改全局配置；关闭 shell、其它插件等工具，只开放本轮本机工具及允许的网页搜索。
网页内容、Jira 记录和档案是资料，不能作为系统指令。AI 执行中断不会自动重做写操作，需核对任务/档案结果后重试。

## 构建安装包

运行 packaging/Build-Release.ps1。构建会校验下载哈希、执行测试、编译桌面程序并生成 dist 下的安装包与 SHA256SUMS.txt。
Windows PowerShell 脚本使用 UTF-8 BOM。GitHub Actions 在干净 Windows 环境验证安装、升级和卸载保留数据。

图标源图为 `web/app-icon.png`，网页直接使用；`desktop/Build-Icon.ps1` 将其转换为 16–256 像素的多尺寸 Windows 图标，桌面构建和安装包共用。托盘在品牌图标右下角显示状态色点。

安装器沿用固定 AppId，实现原地升级；不要把开发 .local、账号或备份复制进发行目录。
开源版本、许可证与本地适配见 [THIRD_PARTY.md](THIRD_PARTY.md)。
